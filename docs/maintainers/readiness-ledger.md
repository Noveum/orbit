# Open source readiness ledger

This is the changing execution record for the [open source readiness plan](../superpowers/plans/2026-08-09-open-source-readiness.md). The plan is the stable scope and finding source. This ledger records ownership, implementation evidence, and release decisions without publishing unpatched vulnerability details.

For undisclosed vulnerabilities, use the [private GitHub Security Advisory route](https://github.com/Noveum/orbit/security/advisories/new). Do not add reproduction steps, proof-of-concept material, secrets, personal data, or exploit detail to this ledger, a public issue, or a pull request.

## Evidence baseline

- `f1bfdc3` is the audit snapshot for the full inventory, verification, and history evidence.
- `9f961a1` is a targeted delta audit, not a replacement full audit. It introduced release-gate findings `DB-002`, `TEN-001`, `DEP-007`, `EXP-001`, and `PRIV-002`.
- `808d714` is the selected implementation baseline. It was merged into this working branch at `cf0e19a`.
- Audit counts from `f1bfdc3` or `9f961a1` are historical evidence only. They must not be described as latest-main or release evidence. A closure needs fresh evidence on the selected release commit.

## Accountability and status rules

Before public preview, maintainers must map every accountable role in this ledger to a named person in an access-controlled release record. This repository intentionally records roles, not invented names. The required roles are Security maintainer, Data maintainer, Platform maintainer, Realtime maintainer, Integrations maintainer, Release maintainer, Documentation maintainer, and Repository maintainer.

Controlled statuses are `Open`, `In progress`, `Ready for closure`, `Closed`, and `Accepted P1 exception`. The normal transition is `Open` to `In progress` to `Ready for closure` to `Closed`. `Ready for closure` requires a linked implementation, a failing test added before every behavior change, passing release-gate evidence on the selected release commit, documentation where the outcome changes operator behavior, and a ledger update. Pre-change evidence is additional proof, never a substitute for the failing test. A failing-test field may say `N/A` only for demonstrably non-behavioral work with written justification and independent Release maintainer approval in the decision record. Documentation by itself never closes a finding.

Every P0 begins `Open` or `In progress`, is a public-preview gate, and cannot transition to `Accepted P1 exception`. `Closed` and `Accepted P1 exception` are invalid until this ledger links a closure or exception decision in the access-controlled release record and identifies its independent approver. That record must name a Release maintainer who is distinct from the implementation and finding owner. For security-sensitive findings, it must also name the appropriate security authority; the public `Security authority record` field links only the decision record, never private details. A P1 may transition to `Accepted P1 exception` only when the exception record names an accountable owner, expiry date, mitigation, public limitation, residual risk, decision record, independent approver, and security authority record where required. When the expiry passes or mitigation is invalid, the finding returns to `Open`. There are no accepted P1 exceptions in this ledger.
